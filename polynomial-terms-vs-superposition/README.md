# Polynomial Terms vs Superposition

<p align="center">
  <strong>An interactive visualization of polynomial basis terms and their cumulative combination.</strong>
</p>

<p align="center">
  See how x, x², x³, … are introduced one term at a time and how their cumulative sums form progressively higher-order polynomial expressions.
</p>

---

## Overview

This project is an educational visualization of a simple but important idea in polynomial modeling:

> A polynomial can be constructed by combining powers of the input variable.

The visualization presents the same progression in two synchronized views:

- **Individual Terms** — the individual powers `x`, `x²`, `x³`, …, `x²⁰`
- **Superposition** — the cumulative sums `x`, `x + x²`, `x + x² + x³`, …, `x + x² + ... + x²⁰`

The two plots advance together as the polynomial order changes.

The project is intended to help learners connect:

```text
Individual basis terms
        ↓
Linear combination of terms
        ↓
Polynomial expression
        ↓
Increasing polynomial order
```

The word **superposition** is used here in the algebraic sense of adding the individual polynomial components together. It is not intended to claim a connection to neural-network superposition or mechanistic interpretability.

---

## What the visualization shows

At order `n`, the application has generated polynomial terms from order 1 through order `n`.

For example, at order 4:

### Individual Terms

```text
y = x
y = x²
y = x³
y = x⁴
```

### Superposition

```text
y = x
y = x + x²
y = x + x² + x³
y = x + x² + x³ + x⁴
```

The left and right panels are synchronized, so the learner can see the individual components and their cumulative combinations at the same order.

---

## Mathematical formulation

The individual term of order `k` is:

```text
φₖ(x) = mₖ xᵏ
```

The cumulative expression through order `n` is:

```text
fₙ(x) = Σₖ₌₁ⁿ mₖ xᵏ
```

In the current implementation, every coefficient is set to `1`:

```text
m₁ = m₂ = ... = m₂₀ = 1
```

Therefore the actual expressions displayed by the current experiment are:

```text
f₁(x)  = x
f₂(x)  = x + x²
f₃(x)  = x + x² + x³
...
f₂₀(x) = x + x² + x³ + ... + x²⁰
```

### Important scope of the current formulation

This experiment deliberately starts at `x¹`.

Therefore, it does **not** include a constant term such as `m₀`.

A general polynomial can contain:

```text
m₀ + m₁x + m₂x² + ... + mₙxⁿ
```

whereas this visualization uses the restricted form:

```text
m₁x + m₂x² + ... + mₙxⁿ
```

with all current coefficients equal to `1`.

## Individual Terms

The left panel contains one curve for each polynomial power:

```text
x
x²
x³
...
x²⁰
```

The Python program calculates these curves independently.

For order `k`:

```text
y = mₖ xᵏ
```

Since the current coefficient vector is:

```python
coefficients = [1.0] * MAX_ORDER
```

the current individual curves are simply:

```text
y = xᵏ
```

for `k = 1, 2, ..., 20`.

---

## Superposition

The right panel contains cumulative sums.

For each order `n`, the program starts from zero and adds all terms from order 1 through `n`.

For example:

```text
Order 1:
x

Order 2:
x + x²

Order 3:
x + x² + x³

Order 4:
x + x² + x³ + x⁴
```

At order 20:

```text
x + x² + x³ + ... + x²⁰
```

The cumulative curves are calculated independently for every order before the HTML application is generated.

## Why the two views are useful

The visualization separates two ideas that are often introduced together in a polynomial equation.

### View 1 — Components

```text
x
x²
x³
x⁴
...
```

Each term is treated as an individual function.

### View 2 — Combination

```text
x
x + x²
x + x² + x³
x + x² + x³ + x⁴
...
```

The second view shows how the individual components can be combined to construct progressively richer polynomial expressions.

This provides an intuitive bridge to the idea of **basis functions** and **linear combinations**.

## Maximum polynomial order

The current default is:

```python
MAX_ORDER = 20
```

Therefore the experiment contains orders:

```text
1, 2, 3, ..., 20
```

and generates:

```text
x¹, x², x³, ..., x²⁰
```

The same `MAX_ORDER` controls the number of individual and cumulative curves generated by the Python program and the number of orders available to the browser animation.

---

## Coefficients

The current experiment uses equal coefficients:

```python
coefficients = [1.0] * MAX_ORDER
```

Therefore:

```text
m₁ = m₂ = ... = m₂₀ = 1
```

This is intentional. Equal coefficients make the visualization focus on the effect of adding polynomial terms rather than on the effect of different coefficient magnitudes.

The Python implementation is nevertheless written so that the coefficient array can be changed for future experiments.

For example, a different coefficient vector could produce:

```text
m₁x + m₂x² + m₃x³ + ...
```

with different contributions from each basis term.

## Curve evaluation range

There is an intentional distinction between the visible X-axis and the range used to calculate the curves.

### Visible X-axis

```text
-2 ≤ x ≤ 2
```

### Curve evaluation range

```text
-1 ≤ x ≤ 1
```

The Python source defines:

```python
X_AXIS_MIN = -2
X_AXIS_MAX = 2

X_DRAW_MIN = -1
X_DRAW_MAX = 1
```

This choice is particularly important for high-order powers.

For example:

```text
2¹⁰ = 1,024
2²⁰ = 1,048,576
```

Higher powers can therefore grow very rapidly outside the interval around zero.

Restricting the actual curve evaluation to `[-1, 1]` keeps the high-order terms within a visually manageable range while the axes still provide surrounding coordinate context.

---

## Curve resolution

The curves are sampled at:

```python
N_POINTS = 1200
```

The X-values are generated using:

```python
np.linspace(-1, 1, 1200)
```

Each curve therefore contains 1200 sampled points before being passed to Plotly.

This controls the sampling resolution of the displayed curves; it is not a parameter related to model training or dataset size.

## Interactive interface

The generated HTML application contains two synchronized Plotly graphs and five navigation/control buttons plus a status display.

### Previous

Moves the current order down by one.

```text
Order 8 → Order 7
```

The button is disabled at order 1.

### Next Order

Moves the current order up by one.

```text
Order 7 → Order 8
```

The button is disabled at the maximum order.

### Play

Starts automatic progression through the orders.

If the current order is already the maximum order, Play resets the current order to 1 before starting.

### Pause

Stops the automatic progression and leaves the current order visible.

### Reset

Stops the animation and returns the visualization to:

```text
Order 1 / 20
```

### Speed

Cycles through four animation speeds:

```text
0.5×
1×
2×
4×
```

The corresponding timer delays are:

| Speed | Delay |
|---:|---:|
| `0.5×` | `2000 ms` |
| `1×` | `1000 ms` |
| `2×` | `500 ms` |
| `4×` | `250 ms` |

The default speed shown by the interface is `1×`.

If the animation is running when the speed is changed, the current timer is restarted using the new delay.

## How synchronization works

The Python program creates 20 traces in each Plotly graph.

Initially, only the first trace is visible.

The browser maintains:

```javascript
let currentOrder = 1;
```

When the order changes, the JavaScript creates a visibility array in which the first `currentOrder` traces are visible.

Conceptually:

```text
Order 1:
✓ term 1
✗ term 2
✗ term 3
...
✗ term 20

Order 3:
✓ term 1
✓ term 2
✓ term 3
✗ term 4
...
✗ term 20

Order 20:
✓ term 1
✓ term 2
...
✓ term 20
```

The same visibility pattern is applied to both Plotly graphs.

Thus the two panels always remain synchronized to the same current order.

---

## Dynamic equation display

The header above the plots is updated whenever the order changes.

For example, at order 3 it displays:

```text
Order 3 / 20

Left: y = x^3
Right: y = x + x^2 + x^3
```

The left equation represents the individual term associated with the current order.

The right equation represents the cumulative sum through the current order.

The equations are generated dynamically by JavaScript rather than being hard-coded separately for every order.

## Educational interpretation

This visualization can be used to introduce polynomial models from a basis-function perspective.

A learner first sees individual functions:

```text
x
x²
x³
x⁴
...
```

and then sees those components combined progressively:

```text
x
x + x²
x + x² + x³
x + x² + x³ + x⁴
...
```

This provides a visual bridge to:

- Polynomial functions
- Basis functions
- Linear combinations
- Polynomial feature expansion
- Parameterized mathematical models
- Model complexity

The visualization does **not** perform regression or learn coefficients from data. The coefficients are explicitly specified in the Python source and are currently all equal to 1.

---

## What this project does not demonstrate

It is important not to overinterpret the visualization.

This project does not demonstrate:

- polynomial regression,
- parameter estimation from observations,
- training a machine-learning model,
- optimization,
- gradient descent,
- overfitting,
- test-set performance,
- regularization,
- neural-network superposition.

Instead, it demonstrates a more basic mathematical construction:

```text
Individual polynomial terms
        ↓
Cumulative linear combination
        ↓
Higher-order polynomial expression
```

This makes it suitable as a conceptual building block for later topics.

---

## Numerical considerations

The current visualization deliberately evaluates the curves only on `[-1, 1]`.

This is important because high-order powers can grow rapidly outside this interval.

For example:

```text
2²⁰ = 1,048,576
```

whereas:

```text
1²⁰ = 1
```

Consequently, extending the evaluation range substantially beyond `[-1, 1]` can make high-order terms dominate the plotted scale very quickly.

The current range is therefore part of the visualization design, not a limitation of polynomial mathematics itself.

---

## Why the constant term is omitted

The current experiment begins with:

```text
x
```

rather than:

```text
1
```

and therefore uses:

```text
m₁x + m₂x² + ... + mₙxⁿ
```

instead of the fully general polynomial:

```text
m₀ + m₁x + m₂x² + ... + mₙxⁿ
```

This keeps the visual progression focused on the addition of increasingly higher powers of `x`.

Adding a constant basis term would be a possible future extension.

## Potential extensions

The current project provides a simple foundation for additional educational experiments.

### Adjustable coefficients

Allow users to change the coefficient associated with each basis term.

### Constant term

Add the `x⁰ = 1` basis function.

### Weighted superposition

Demonstrate how different coefficient magnitudes change the resulting polynomial.

### Basis comparison

Compare the standard polynomial basis:

```text
1, x, x², x³, ...
```

with other bases such as orthogonal polynomial bases.

### Polynomial regression

Introduce observed data and estimate the coefficients from the data rather than specifying them manually.

### Model complexity

Connect the number of polynomial terms to model capacity and later introduce underfitting and overfitting using a separate regression experiment.

### Interactive coefficient controls

Allow learners to change individual coefficients and immediately observe their effect on both panels.
